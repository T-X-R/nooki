# Create and edit Library documents

Use **+ → New document** on **My documents** or any folder. Nooki immediately creates an empty **Untitled document** at that location and opens it. **New folder** immediately creates an empty **Untitled folder**, with inline renaming ready; sibling duplicates receive a numbered suffix. Neither operation opens a dialog. Root creation never creates a folder. Imports retain their file picker and review step.

The title and body are always editable on a continuous, borderless document surface. Clicking either adds no input frame. The body fills the remaining paper area, including blank space. Edit the formatted body directly with the rich-text editor; Markdown source is never shown. No toolbar occupies a permanent row. Selecting body text shows a floating bold/italic/strikethrough/inline-code toolbar beside the selection, without shifting the page. Collapsing the selection, leaving the editor or pressing Escape dismisses it. Type `/` in an empty paragraph to insert headings, lists, tasks, quotes, code blocks, tables or dividers. Undo/redo remain available through standard keyboard shortcuts. Changes autosave after a pause or when leaving the editor; Cmd/Ctrl+Enter saves immediately. Empty bodies are valid. Titles are required. Local drafts survive navigation/restart and backup. Failed writes keep the draft for retry; version conflicts cannot overwrite a newer revision and offer an explicit discard-and-reload action. Reading a document does not rewrite its Markdown. Retained citation snapshots remain read-only.

Directory document/folder menus start with **Add to conversation**. A folder appears as one compact name/count attachment without a disclosure tree, while retaining its entire selected hierarchy, including empty descendants. Every live document is captured as a retained source when sending; repeated references share one document snapshot. The existing limit of 50 documents is explicit and never silently truncates a folder. Removing a folder attachment removes the whole selection. The title and full hierarchy travel with the conversation task and agent context.

The document’s top-right menu contains **Export Markdown** and **Version history**. History opens a closable right-hand panel with hidden scrollbars and normal scrolling, never a modal. Selecting a version previews its title and formatted content read-only in the original document pane; it does not publish or edit the current document. Closing the panel returns to the editable current document. **Restore this version** explicitly makes the selection current and keeps the panel open on the restored version. Keep at most 10 versions including current (nine historical revisions); successful publication prunes older stored revisions, and reads cap legacy history immediately. Retained citation snapshots are independent of history pruning. Desktop export opens the native Save dialog for the current `.md` document; cancelling does nothing. The file contains the saved Markdown body exactly, with the title used as its proposed filename. No ZIP or download path appears in the Library. Browser preview uses an ordinary `.md` download.

Document/folder ellipsis menus provide rename and move; documents also offer Trash and supported capability authorization. Drag documents or folders into a directory folder or root. Folders can also be dragged from the content list. Invalid parents, cycles and duplicate sibling names fail without changing membership, content or history. Move dialogs remain the keyboard alternative. Deleting a folder confirms removal of the folder and all descendants; every contained document moves to Trash, without moving children or documents to the parent. Version history and citation snapshots remain intact. Folder structure is deleted; document recovery uses the existing Trash flow. The document selection checkboxes and batch action bar are removed.

See [Library folders](library-folders-design.md) for layout, migration and storage contracts.
