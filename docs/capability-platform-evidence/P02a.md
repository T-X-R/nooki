## Experiment and trust boundary

`src-tauri/examples/capability_runtime_probe.rs` is a separate executable with its own embedded
configuration and fixtures. It reuses only the opt-in profile configuration, not the production
application context, services, plugins or capability loader. Run it through the P00 launcher in an
empty home. Four native windows use separate nonpersistent WKWebView stores and the same synthetic
custom-protocol origin: shell, package A, package B and an unrestricted-CSP control.

Only fixed synthetic assets are served. CSP restricts A/B/shell resource loading, new windows and
navigation are denied, and native commands bind the caller to the actual WebviewWindow label. One
intentionally unguarded command returns a fixed synthetic sentinel to test Tauri's default exposure.
The test has no real secret, file-access command or agent connection. Its TCP and UDP receivers bind
only `127.0.0.1` on ephemeral ports. Native positive controls prove all eight receivers were active.

The fixture deliberately attempts local HTTP fetch, beacon, WebSocket, image, popup and WebRTC STUN
traffic. Native receiver events are authoritative; a JavaScript return value is not proof of denial.
The probe's native event log is bounded to 256 entries and contains no message bodies or credentials.

## Observed results

| Requirement | Actual evidence | Interpretation |
|---|---|---|
| Shell/private storage | A/B/control read no shell sentinel; all began with an empty marker and retained their own marker after concurrent writes | Separate nonpersistent stores worked despite identical origins |
| DOM/window access | Each view had `parent === window`, no opener, and denied creation of a named shell popup | No parent/opener DOM route was exposed in this topology; this does not prove future embedded-child or iframe behavior |
| Caller spoofing | Unknown owner rejected in the first run; a fresh rerun also rejected A/B/control claiming the existing shell identity and shell claiming A. Own 0/1,024/65,536-byte payloads echoed exactly | Native label binding is feasible; not the future activation/grant model |
| Internal native access | Protected shell command denied for A/B/control; core window-title mutation denied; **unguarded app sentinel reachable from all views** | Default app-command registration is insufficient; production must close every non-broker command path |
| HTTP/WebSocket egress | A/B/shell: zero non-control TCP receipts; control: four | CSP blocked the tested HTTP-family routes |
| WebRTC egress | **Four non-control UDP receipts from every view, including CSP-restricted A/B/shell** | **Failed. CSP plus separate views does not enforce the design's egress invariant** |
| Beacon return value | `sendBeacon` returned true in restricted views, with no TCP receipt | A browser's success-like return value cannot substitute for network observation |
| Assets and media | All views loaded a 16×16 SVG and parsed a 0.125-second PCM WAV | Custom-protocol assets and media metadata work; actual playback/seek/background services remain untested |
| IPC size | 65,536 bytes accepted, 65,537 rejected; observed round trips 0–7 ms over the twelve samples | A bounded control-message path is feasible; this is not a throughput benchmark or streaming limit |
| Infinite-loop containment | A stopped at heartbeat 378, consumed 97.1% CPU in its own WebContent process; shell/B/control continued | The actual hostile loop did not block host control or peers |
| Forced stop | Shell `destroy()` removed A; the recorded A process disappeared while shell/B/control remained; later ticks B=406, control=407, shell=317 | Actual process exit was observed, not inferred from a closed window or successful IPC reply |

The native stop request returned before window removal completed. The later status sample (4.632 s
after the request) had no A window. Do not report the request's 0 ms dispatch time as termination
latency. The external `ps` samples confirmed PID 47257 at 97.1% CPU before destruction and absent
afterward; PIDs 47249/47258/47259 remained. Per-view RSS in those samples was roughly 20–27 MB,
excluding shared network/GPU/native processes. These are observations, not supported resource budgets.

The WebContent PID is read using WebKit's private `_webProcessIdentifier` selector after checking
availability, solely to correlate diagnostic process observations. It is never used to authorize or
kill a process. This private diagnostic is not proposed as a production dependency.

## Verification and reproduction

1. `cargo test --offline --example capability_runtime_probe` in `src-tauri`: one focused test passed.
   The caller/size test was observed failing before implementation.
2. `cargo build --offline --example capability_runtime_probe`: passed with no warnings after removing
   an initial duplicate embedded-context link. `node --check` passed for the fixture script.
3. From the repository, create a new profile with `node scripts/desktop-profile.mjs create`, then:

   ```sh
   node scripts/desktop-profile.mjs launch <printed-profile-directory> src-tauri/target/debug/examples/capability_runtime_probe
   ```

4. Activate the running probe. In its Window menu select **probe-shell**. Click **Run boundary probes**,
   wait for all four reports in `<profile>/events.json`, then click **Start infinite loop in A**.
5. Inspect only the WebContent PIDs recorded by this run using `ps -p <ids> -o pid,pcpu,rss,time,comm`.
   Click **Destroy A**, then **Native status**. Verify A disappears, its process exits and peers continue.
6. Quit the probe normally. A five-minute native watchdog also exits the disposable executable.

This run used `/private/tmp/nooki-profile-B0QVfd`. A temporary `.app` wrapper under
`/tmp/nooki-p02/Nooki Runtime Probe.app` made it selectable by the desktop automation tool; it did
not install over Nooki. The wrapper contained the compiled example and a minimal Info.plist only.
Both runs exited zero after normal Quit. The identity rerun used `/private/tmp/nooki-profile-wnsEB7`;
only the spoofed-owner argument changed. The unchanged loop/termination evidence is reused from the
first run. Its full rerun trace remains in that profile, with selected identity fields committed above.
Screenshot: `/tmp/nooki-p02/native-stop.png`.
Logs: `/tmp/nooki-p02-policy-red.log`, `/tmp/nooki-p02-unit.log`, `/tmp/nooki-p02-build.log`,
`/tmp/nooki-p02-run.log`. The full `cargo test --offline` regression passed: 129 top-level tests plus a child-process assertion,
with two pre-existing live-agent tests ignored. The production app's required build/install and
signature verification passed; logs are `/tmp/nooki-p02-app-build-final.log` and
`/tmp/nooki-p02-app-install.log`. No production runtime behavior was changed.

## Remaining work

P02b must resolve the demonstrated UDP escape and default app-command exposure before selecting a
production topology. It must also establish budgets, media playback/cleanup, additional outbound
channels, and embedding constraints. A native engine-level deny mechanism or a separately sandboxed
runtime needs another measured experiment; deleting a JavaScript global alone is not sufficient proof.
The candidate comparison is in [ADR 0007](../adr/0007-capability-runtime-isolation-experiment.md).
