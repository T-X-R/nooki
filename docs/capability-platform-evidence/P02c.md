## Experiment and reproduction

This extends the [same-window experiment](P02b2b2a.md) with a native `probe_load` command.
It authenticates the receiving Webview label and immediately admits or refuses work using four
fixed experimental limits: 65,536 bytes per payload, four operations per caller, six operations
globally and 262,144 payload bytes globally. There is no additional admission queue. The permit
owns its capacity until the operation returns or its future is dropped. Its two-second delay
retains the actual payload; the response reports byte length and checksum after that delay.

These are experiment values, not frozen public quotas. The state is local to this disposable
example. Existing echo/report/heartbeat commands and framework-internal IPC do not use this limiter.

Build with `cargo build --offline --example capability_runtime_probe --features runtime-probe-embedded`
from `src-tauri`, copy into the temporary probe bundle described in P02a, create a fresh profile
with `node scripts/desktop-profile.mjs create`, then launch through the profile helper. This run used:

```sh
node scripts/desktop-profile.mjs launch /private/tmp/nooki-profile-zCXDT3 '/tmp/nooki-p02b/Nooki Runtime Probe.app/Contents/MacOS/probe'
```

Select the embedded workspace from the Window menu, click **Run IPC load probe**, request
**Native status** during load, switch to B, and request status after both reports finish. Each
caller issues twelve concurrent requests for each of three payload sizes: 1, 65,536 and 65,537
bytes. Each caller waits 2.5 seconds between its rounds; this is a bounded burst fixture, not a
cross-view scheduling barrier. Both then run a synthetic failure followed by a successful recovery.
Quit normally. This run exited 0, with no watchdog termination. No ordinary user data or external
services are involved. Existing boundary/channel/audio results remain in their prior receipts;
those full sequences were not repeated during this load-only run.

All ten accepted burst responses returned exact lengths and checksums, in 2,003–2,010 ms.
All 62 rejected burst requests returned before the two-second operation delay. The count of
`rejected: 38` in native snapshots measures capacity refusals only; the 24 oversized requests
are rejected before those counters and must not be omitted from the reported total.

At 160,919 ms the native status shows four A operations holding exactly 262,144 bytes; its retained
peaks are six operations and 262,144 bytes. Shell, A and B heartbeats advance from 183/184/21 at
load dispatch to 189/189/25 at that occupied snapshot. Switching to B succeeds at 165,236 ms.
Both callers report the expected synthetic operation failure, then successful recovery with
9 bytes and checksum 959. At 172,558 ms, native status shows zero operations, zero bytes and an
empty caller map, with shell/A/B heartbeats at 204/201/38. The visible B result and native status
were checked through the desktop UI before quitting.

The shell's recorded native dispatch duration is 0 ms at millisecond resolution. This is not an
end-to-end UI latency measurement or a service-level guarantee. Hidden-view timer throttling is
present, so heartbeat progress establishes liveness only. A consumes the entire byte budget during
the large round and B receives no slot in that round: bounded admission does not establish fairness.

## Limits and next work

Tauri decodes the request into a `String` before this handler checks its size or acquires capacity.
The experiment therefore bounds admitted operation payloads, not JavaScript allocations, native
transport buffers, serialization overhead, framework queues or total process memory. It does not
show that a malicious sustained flood is contained. The burst size is deliberately finite.

The cancellation test explicitly aborts a Tokio future and observes permit release. Closing a
Webview was not tested as cancellation of an in-flight native command; there is no new connection
between those lifetimes. The current synthetic operation normally finishes after two seconds.
Generation-scoped cancellation and production cleanup must be implemented and verified by their
owning runtime tasks, not inferred from RAII alone.

P02c's measured admission slice is complete. P02d retains archive/storage/transfer/event/run/service
budgets and P02e retains the topology/support decision, including the unresolved pre-admission
allocation boundary. P02, its resource-budget parent and K0 remain incomplete.
