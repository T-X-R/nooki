## Reproduction and test ordering

Build with `cargo build --offline --example capability_runtime_probe` in `src-tauri`. Use the P02a
temporary-bundle procedure, create a fresh profile with `node scripts/desktop-profile.mjs create`,
and launch that bundle through `scripts/desktop-profile.mjs launch`. The final run used:

```sh
node scripts/desktop-profile.mjs launch /private/tmp/nooki-profile-jZxU4F '/tmp/nooki-p02b/Nooki Runtime Probe.app/Contents/MacOS/probe'
```

The profile path identifies this run; use a newly created profile when reproducing. Synthetic
loopback receivers and silent WAV data were the only inputs. No ordinary data, credentials, external
service or real agent were used.

1. Select `probe-shell` through the Window menu. Run **Run channel scope probe first**, once.
   Its first large shell channel message has queue data ID 0. The shell deliberately holds its
   JavaScript event loop for 2.5 seconds while native code dispatches foreign-read attempts to A/B
   and the control. It then resumes and receives the owner message through the normal Tauri path.
   The native fixture rejects running this after baseline probes or a prior channel probe.
2. Run **Run boundary probes**. The WAV is now a 60-second PCM sample (960,044 bytes), replacing the
   original 0.125-second sample for meaningful playback observations.
3. Select A and click **Play test audio**. Return to shell and click **Native status** to record
   continuing playback while A has lost focus. Return to A, click **Pause and release audio**.
4. Run **Run additional network probes** from shell. This navigates only the unrestricted control
   to its loopback response; select shell again if the control comes forward. Run this after channel
   and baseline probes, because the control deliberately leaves the fixture page.
5. Start the infinite loop in A, record native status, destroy A, then record status again. Quit via
   the normal app menu. This run exited with code 0; no watchdog termination was needed.

## Failed initial methods and coverage limits

The first run (`/private/tmp/nooki-profile-Tie7EF`) already reproduced preconnect escape. Its attempt
to hold a channel by replacing `__TAURI_INTERNALS__.invoke` did not work because Tauri defines that
property without making it writable. No channel-isolation conclusion is taken from that run.
The final bounded event-loop hold replaces the method and demonstrates a genuinely pending message.
Its known ID is specific to the first large channel transfer on a fresh view; it is not an API or
authorization token. The production transport must still validate generation/closure semantics.

The original 0.125-second looping WAV repeatedly sampled at the endpoint and failed the pause-time
comparison, so it did not establish continuous playback. The longer sample supplies actual progress
and pause evidence. Loop boundaries, seeking, audible hardware output, other codecs, background
services across page destruction and native resource-handle counts remain unverified.

Pinned Tauri source scopes `ChannelDataIpcQueue` by calling webview and initializes each view's data
sequence at zero; `fetch` looks up the native caller's queue. This source inspection and the live
foreign/owner experiment cover that specific framework exception. They do not certify all internal
IPC paths. DNS getter inspection is similarly narrower than network capture.
