# C06b2: Native Agent review and installation authority

- Date: 2026-11-26; based on `8976dde`, existing feature branch and PR #38.
- Scope: native review/controller and distinct manifest permission. This adds no Tauri command,
  public `host.agents` API, Agent process, model turn or installed test package.
- Platform/app/contract: 0.12.0. Developer kit: 0.11.0 targeting platform 0.12.0.

## Behavior and boundaries

`capability_agent_review.rs` accepts a bounded proposal from the trusted Host controller. Native
state owns the immutable intent, installation generation, restore scope, policy digest, review
handle and deadline. Returned pending-review data includes the frozen intent for the future Host
review UI. Package-provided approval, owner, policy and scope fields are rejected. An opaque run ID
is insufficient to read or claim another installation's run.

The controller requires the independent `agents.run` permission. Existing `ai.invoke` neither
implies that grant nor acquires run-management authority. Native manifest validation and the
portable kit require minPlatformVersion 0.12.0. Types, kit metadata and the import permission label
are aligned. Public methods remain absent, and the contract/Skill explicitly say so. This permission
alignment was moved forward from C06d; it is not public Agent-service delivery.

Begin checks current installation, native policy availability and selected-source authority. Host
approval rechecks installation, policy and expiry inside data/authority fences before the durable
journal commit; selected text comes from the existing native grant owner. The first submission
claim rechecks policy and source authorization against the immutable stored run under the same
fences. Callback shape now receives that exact run rather than requiring an unfenced pre-read.

Observation and exact committed replay return metadata only. They do not recapture inputs or
submit work. Once submission has been claimed, later source revocation or adapter unavailability
cannot reclassify the unknown external outcome as a retryable new failure. The caller must reconcile
the existing identity. Dismissing an unapproved review grants nothing; dismissing a review after its
approval committed does not undo that record. Explicit run cancellation remains C06c/C06d.

The native policy resolver is an internal synchronous adapter-owner callback. Tests supply a
deterministic available/unavailable policy proof. C06c must derive it from the real installed adapter
and the complete bounded configuration, enforce that policy and reconcile native submission IDs.
No production adapter policy is claimed from these controller tests. Only Codex proposals are
currently admitted; other adapters fail explicitly until their policies are verified.

The `main` caller label is the existing trusted-legacy Host convention, not hostile-package
containment in the shared JavaScript realm. R02/R03 still own the production isolation boundary.

## Verification

Twelve native controller tests cover:

- Host-only begin/approval/claim, no effect before approval, stable replay across restart and foreign
  run refusal;
- dismissal, expiry before and during policy validation, changed/unavailable/unsupported policies;
- native source selection ownership and revocation before review, approval and first claim;
- disable/re-enable, update, uninstall/reinstall, permission removal and old `ai.invoke` refusal;
- changed immutable requests, request-ID collisions, forged authority fields and failed writes;
- successful/interrupted restore, bounded review capacity and pending-review loss on restart;
- kernel-backed data and installation fences held during policy decisions;
- pending submission remaining unknown after source revocation, without resolving a new policy.
