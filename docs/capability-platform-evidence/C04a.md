## Persisted contract

The native task board retains a `revisionSequence` even after every card is deleted. Changed/new cards
draw a positive JavaScript-safe integer from that sequence; unchanged cards retain their revision.
Comparisons exclude only the revision field itself. The value is opaque, not a per-card edit count.
Every ordinary save passes through the same allocator under `task-data.lock`: legacy UI edits, native
Goal transitions, capability creation/delegation and the older native storage helper. Caller-supplied
card/sequence values cannot choose the committed version. A Goal history response uses the saved card.

Old boards are validated and deterministically normalized in memory on read; reading does not rewrite
their bytes. Existing card revisions and retained create receipts establish the initial sequence floor.
The next save persists metadata. Invalid persisted versions/sequences fail, and sequence exhaustion
refuses new/changed cards before file replacement. Precommit I/O failures leave the committed sequence
unchanged. A post-rename durability failure retains the existing `OUTCOME_UNKNOWN` recovery semantics.

Capability creation allocates the same version for the new card and its durable receipt. Exact replay
continues to return the original reference, including after edits/deletion; it does not report current
state. The Host response validator accepts positive safe-integer versions instead of requiring 1.
No task execution or acceptance authority is added.

Backup restoration remains an explicit rollback boundary: it can restore an older sequence/receipt
set and invalidates capability authority through the existing restore lifecycle. Restored Goal content
changes (pause/restored flags) receive new versions relative to that backup; unchanged drafts retain
theirs. Future task grants must bind this lifecycle as well as the task revision.

## Regression and review evidence

- Six initial revision tests failed before implementation (`/tmp/nooki-c04a-red.log`). They cover
  legacy read migration, affected-only edits/forged versions, deletion/restart, Goal transitions,
  precommit failure/retry and invalid persisted metadata.
- Three additional revision tests cover safe-integer exhaustion, restore-induced changes and the
  older native storage helper sharing the worker's sequence.
- Board creation coverage now seeds a user draft, creates at revision 2, edits to 3, and replays 2
  without changing the edited card. Actual Host adapter coverage creates/replays a second item.
- Independent bounded review found a stale local clone in the history response and the older native
  storage helper bypass. Both were actionable and fixed. The history regression reproduced returned
  revision 16 versus committed 17 before the fix (`/tmp/nooki-c04a-history-red.log`).
- A second bounded pass reproduced the helper dropping an omitted receipt ledger
  (`/tmp/nooki-c04a-helper-red.log`). Both draft writers now share the existing legacy-save path,
  retaining native receipts/provenance and Goal ownership rather than duplicating those rules.
  The third pass found no further concrete issue in that extraction or integration.
- Final contract inspection found the Host's literal-1 result validator. The actual adapter reproduced
  `OUTCOME_UNKNOWN` after its second create (`/tmp/nooki-c04a-adapter-red.log`); the corrected validator
  and regression cover the public native boundary, not only direct worker calls.
- Final native regression: 210 top-level tests pass, plus one nested profile child result; two existing
  live-agent tests remain ignored. This includes 32 board tests, 9 revision tests and 8 Goal tests.
  Full JavaScript regression: 175 platform + 5 capability tests pass. The independent kit scaffold
  test typechecks/checks/packs outside the checkout while reusing installed test dependencies.
- Kit export `/tmp/nooki-c04a-kit.zip` contains kit 0.6.0/platform 0.7.0 and the canonical updated guide.
  This slice adds no package UI; existing selected-document ZIP acceptance remains in C03c/K1.

## Installed binary verification

The rebuilt `/Applications/Nooki.app` native worker was exercised through its real Unix socket in a
fresh isolated profile, with synthetic records and the queue paused. The retained
[state receipt](C04a-installed-state.json) records the final board and checks. This is installed-worker
acceptance, not a new WebView/UI test.

| Operation | Observed result |
|---|---|
| Read two old drafts | Revisions 1 and 2; original disk bytes unchanged |
| Edit first draft and forge both version fields as 999 | First becomes 3, second remains 2, sequence 3 |
| Force pending-file creation failure | Error; committed board bytes unchanged |
| Remove failure and retry | First advances once to 4 |
| Delete all cards, stop/restart worker, recreate same ID | New revision 5 |
| Add Goal while queue paused, then stop it | Revision 6 advances to 8 across two saved transitions; draft stays 5 |
| Finish both worker instances | Clean exit; no thread ID or agent runtime directory |

Final desktop release compilation: 27.15s; app bundle: 24.63 MiB. Desktop build/install and
strict signature verification pass. The existing large-chunk build advisory
remains. C04a supplies the version foundation; it does not yet expose task selection or attachments,
and the legacy shared-realm package loader remains trusted-only pending R02/R03/K4.
