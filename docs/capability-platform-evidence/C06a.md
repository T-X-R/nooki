## Why the existing chat path is insufficient

Current `ConversationHost::run` routes through the existing Codex/native adapters. Ordinary Codex
chat resumes with workspace writes and may install the Nooki capability dynamic tool. Its request
handler declines unsupported approvals; it is not a general Host-owned package-run approval surface.
The board path has a stricter configuration, but neither path is a ready-made public Agent run API.
C06 will reuse transport and native run identity while explicitly binding a dedicated effect scope.
It will not add a model client, credential store or substitute scheduler.

C06 has been split in the existing checklist into policy feasibility, durable scoped intent,
adapter dispatch/reconciliation, public SDK/Host interaction and independent/real-agent acceptance.
C06 depends on completed C01/C02 and may progress independently of C05c; both remain required for K2.

## Reproducible native probe

```sh
node scripts/probe-capability-agent-policy.mjs /absolute/path/to/codex
```

The probe creates a fresh profile through the existing launcher and uses only new synthetic files.
It passes a child-only environment with an empty Codex home; no credentials are copied or read.
An unsandboxed positive control reads the synthetic foreign file and contacts a localhost fixture
server, proving those resources exist before testing refusal. The native `codex sandbox` then:

- reads approved input and writes its designated output;
- denies the sibling synthetic private file and a symlink to it;
- denies writes to inputs, unrelated files and an output symlink leading outside the output root;
- cannot contact the reachable localhost endpoint; its request counter remains zero.

The script then starts an ephemeral app-server thread with the same named profile, no selected
capability roots/dynamic tools and no turn. It asserts the profile ID, `approvalPolicy: never`,
exact output-only writable roots, disabled network and excluded implicit temporary write roots.
The process is terminated after acknowledgement. **Zero model turns were sent.**

Final profile: `/private/tmp/nooki-profile-WtWdvw`.
Receipt: `policy-probe.json` within that root; sandbox stderr is retained alongside it.
Final log: `/tmp/nooki-c06-policy-probe-final.log`. `node --check` and `git diff --check` pass.

## Failed controls and limits

The initial profile using only `:minimal`, explicit input reads and output writes unexpectedly read
an unrelated synthetic file under `/private/tmp`. Adding a root deny did not prevent that read.
A nonexistent profile was correctly rejected, and an explicit deny for the synthetic foreign path
was enforced; the selected configuration was not simply ignored. Replacing `:minimal` with a small
handwritten runtime-root list caused the sandboxed shell to exit 134, so that candidate was rejected.

The passing probe retains `:minimal` but explicitly denies `/private`, `/Users` and `/Volumes`, with
more-specific grants for input/output directories. This establishes the tested mechanism on macOS
15.6.1 / CLI 0.170.0. It is **not** an exhaustive inventory of every runtime read root or a production
allow-list audit. Before C06a closes, establish the complete effective read scope and fail-closed
compatibility behavior. C06c must additionally validate configuration/connector/tool restrictions,
Host-only approvals/questions, durable reconciliation and cancellation. Neither acknowledgement
nor a successful shell probe proves those later requirements.
