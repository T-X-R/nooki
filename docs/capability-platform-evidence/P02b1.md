## Experiment and reproduction

Build with `cargo build --offline --example capability_runtime_probe` in `src-tauri`. Follow P02a's
temporary macOS bundle procedure with the new executable. Create an empty profile with
`node scripts/desktop-profile.mjs create`, then launch using:

```sh
node scripts/desktop-profile.mjs launch /private/tmp/nooki-profile-UM7JM3 '/tmp/nooki-p02b/Nooki Runtime Probe.app/Contents/MacOS/probe'
```

The recorded profile path identifies this run; create a fresh one for reproduction. No ordinary
Library, credentials or agent configuration were copied. All network targets are synthetic local
TCP/UDP receivers; no external service or real agent was used.

Five nonpersistent views start at `about:blank`. Native code checks and sets WebKit's private
peer-connection preference before navigating to the fixture. Shell/A/B disable peer connections;
the permissive control preserves the enabled setting and omits CSP. The fifth view deliberately
requests a nonexistent selector and must remain blank. Application dispatch allows only RPC, report
and heartbeat commands for A/B; the shell and synthetic control retain baseline command access.
Core/plugin commands follow Tauri's separate ACL path, not this application-command filter.

Using the Window menu, select `probe-shell`, click **Run boundary probes**, wait for result reports,
click **Start infinite loop in A**, inspect native status, then **Destroy A** and **Native status**.
The fixture also attempts WebRTC at its first script execution, before the manual probe. Close via
the app's normal Quit command; this run exited with code 0. Local screenshot:
`/tmp/nooki-p02b/native-stop.png`.

## Observed results

| Check | Actual observation | Meaning |
|---|---|---|
| Receiver positive controls | Each of five views received one native TCP and one native UDP self-check | Empty attempt counts are not explained by failed listeners |
| Restricted egress attempts | Shell/A/B each received 0 non-control TCP and 0 non-control UDP packets | Previously reproduced WebRTC UDP route is closed in this candidate |
| Permissive control | 4 TCP connections, 8 UDP packets across startup and manual probes | The same WebRTC and HTTP fixtures still generate real traffic when unrestricted |
| Before-package ordering | Policy records precede script-start records; shell/A/B report no `RTCPeerConnection` at first script and manual run | Setting took effect before the tested package script; no JavaScript global patch is used |
| Unsupported native control | `available: false`, `readyForPackageNavigation: false`; blank view, no script report or heartbeat | Missing selector refuses package loading; this is a synthetic absence control on the tested OS |
| Application commands | A/B reject unguarded sentinel, host-secret, control and unknown commands at dispatch; shell/control still read the unguarded synthetic sentinel | New handlers do not automatically widen package application-command authority |
| Native caller / core command | Known-owner spoof and core `window.set_title` attempts fail | Native caller check remains effective; sampled core operation is denied by Tauri ACL |
| Allowed RPC / budget | 0, 1,024 and 65,536-byte echoes exact in all four loaded views; 65,537 bytes rejected | Legitimate IPC still works; twelve samples span 0–6 ms, not a throughput or memory-bound guarantee |
| Storage / assets | A/B cannot see shell's synthetic storage; retain their own markers; private route returns 403; all views load 16×16 SVG and 0.125-second WAV metadata | Existing measured storage and static-media behavior survives the controls; playback is still untested |
| Infinite loop | A heartbeat freezes at 140; peers advance from 181 to 220; A measured at 95.6% CPU | Shell and other package views remain responsive during the deliberate loop |
| Destruction | Stop dispatched at 57,330 ms; A absent at status 60,721 ms; native process 55905 gone, peers 55901/55906/55907 alive | Runtime destruction still works; 3.391 seconds is an observation interval, not measured termination latency |

The stop command returned immediately while A was still in the first window list, so dispatch time
is not reported as completion time. Private process IDs were diagnostic only; destruction used
Tauri's ordinary window API. The unavailable-control diagnostic PID was 0 and was not inspected as
an operating-system process.

- GREEN: `cargo test --offline --example capability_runtime_probe` passes both policy tests;
  `/tmp/nooki-p02b-policy-final.log`.
- `node --check src-tauri/examples/capability_runtime_probe/assets/probe.js` passes.
- Probe build passes without warnings: `/tmp/nooki-p02b-build.log`.
- Actual desktop run and independent trace assertions pass for receiver controls, startup refusal,
  command denial, caller spoofing, payload limits, storage and forced-stop observations. This is
  native evidence, not a browser mock. Raw events retain all 50 events below the 256-event bound.
- `cargo test --offline` passes: 130 top-level tests plus one nested subprocess assertion, no
  failures, two pre-existing live-agent tests ignored; `/tmp/nooki-p02b-regression-final.log`.
  The initial run failed in an installer fixture. Its timestamp-only temporary paths can collide:
  the added four-thread regression generated only 2,188 unique paths out of 8,192 allocations
  before the fix. Adding the same atomic suffix used by existing integration fixtures makes all
  8,192 paths unique; all six installer tests pass. Production installer logic is unchanged.
  RED/GREEN logs: `/tmp/nooki-p02b-fixture-red.log`, `/tmp/nooki-p02b-fixture-green.log`.
- `npm run desktop:build` passes (33.69-second native release build, 24.14 MiB app); the existing
  frontend large-chunk advisory remains. `npm run desktop:install` and
  `codesign --verify /Applications/Nooki.app` pass; no running ordinary app needed quitting.
  Logs: `/tmp/nooki-p02b-app-build-final.log`, `/tmp/nooki-p02b-app-install.log`.
  No functional JavaScript app code or dependency lockfile changed.

One earlier run stalled after the first policy record because navigation was dispatched reentrantly
inside Wry's native-view callback. The owned test process was stopped; navigation now dispatches
from a separate thread after the configuration check. That failed initialization run is not used
as containment evidence. Its isolated profile remains `/private/tmp/nooki-profile-8ceZTQ`.

## Limits and next eligible task

This completes the bounded P02b1 measurement only. P02/P02b/K0 remain pending. **P02b2** must cover
additional network routes (including DNS-prefetch, preconnect, frames/workers and navigation),

remains trusted-only, and no pending implementation gate is waived.
