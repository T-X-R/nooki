## Integration and boundary

Wry 0.57.1 `src/wkwebview/mod.rs:294–307` skips registration when the supplied
WKWebViewConfiguration already has a handler for a custom protocol. The experiment pre-registers
native WKURLSchemeHandler objects for A/B's `ipc`, `nookiprobe` and `tauri` schemes. It removes their
native `ipc` script-message handler before package navigation. The trusted shell and unguarded
control retain their original transports. There is no dependency fork or method swizzling.

The handler applies a native-owner rate check, reserves receive capacity, bounds metadata, then
checks the body before copying it into Rust or decoding JSON. Requests are forwarded through
Tauri's existing `Webview.on_message` path using `InvokeRequest`, preserving application policy and
core ACL checks. Identity comes from the configured native view; its current native URL supplies
the invocation URL. A caller-provided owner or Origin does not establish identity. The direct
InvokeRequest integration is an explicitly unstable framework interface, not a supported public
Nooki API or an approved production transport.

| Experiment limit | Enforcement / qualification |
|---|---|
| 64 KiB body | Check native NSData length before copying; streamed input reads at most 65,537 bytes and rejects overflow or read failure |
| 2,048-byte URL | Check NSString UTF-16 length and exact UTF-8 length before Rust conversion |
| 32 headers, 128-byte names, 4,096-byte values, 8,192 bytes aggregate | Check before inserting owned header strings into the request map |
| 24 requests/second/native owner | Two fixed owners; finite timestamp history, no waiting queue; rejected attempts do not enter decode |
| 256 KiB reserved body capacity | Reserve the full 64 KiB for every admitted request; this permits at most four simultaneous requests across A/B, including unfinished replies |
| Resource methods | GET/HEAD only, no request body; OPTIONS receives a bounded empty response |
| IPC response | Refuse responses above 64 KiB after the host creates them; this is not a bound on arbitrary host-provider response generation |

The existing operation pool is separate from this receiving pool. The receive reservation is a
capacity accounting value, **not actual RSS**: metadata, decoded JSON, native response data and
framework allocations are additional. Static resource outputs are fixed fixtures; the 960,044-byte
WAV is deliberately outside the IPC-response limit. Production streaming and aggregate response
budgets remain implementation work.

Native task objects remain on the main thread. Completion retains its reservation until the native
reply is delivered or discarded. If Tauri drops the reply closure without invoking it (invalid
invoke key), RAII returns an error reply and releases the reservation. Cancellation removes the
native task and marks it stopped; an already-running bounded operation retains its reservation
until completion, and its late reply cannot call the stopped task. Owner removal clears native task
references; generation checks prevent a completion from targeting a replacement owner.

## Desktop results

Both packages run as separate child webviews in the same workspace window. A retains CSP plus
native policy; B exercises native policy without package CSP. The following results come from the
final binary and profile above, not the earlier debugging runs.

| Case | A | B |
|---|---|---|
| Native script-message fallback | `undefined` | `undefined` |
| Native identity | `probe-a` / `probe-workspace` | `probe-b` / `probe-workspace` |
| 32 KiB echo | Exact round trip | Exact round trip |
| Spoof shell, read host secret, change host window title | All refused | All refused |
| 1 MiB synthetic IPC payload | Rejected before body copy/decode | Rejected before body copy/decode |
| 1 MiB resource POST | HTTP 413, method refused | HTTP 413, method refused |
| 1 MiB POST through `tauri` | CSP blocks load | HTTP 413 from native handler |
| Long URL / oversized header / malformed JSON | HTTP 413 | HTTP 413 |
| Invalid invoke key / abandoned reply | HTTP 400, no timeout | HTTP 400, no timeout |
| Valid local SVG | HTTP 200 | HTTP 200 |
| Abort delayed resource request | AbortError; native cancellation and late-discard recorded | Same |
| 32-request resource burst | 23 accepted / 9 refused | 23 accepted / 9 refused |
| Six concurrent delayed operations per owner | Four accepted / two refused | Six refused while A occupies aggregate capacity |
| Recovery after peer work completes | Successful at 30,549 ms | Successful at 29,045 ms |

No oversized request reaches P02e1's decoded-application or original asset-handler counters. Native
instrumentation distinguishes pre-dispatch rejection from bounded decode. The aggregate receive
peak is **4 requests / 262,144 reserved bytes**; current count and bytes are zero at 43,023 ms and
at the final status. The aggregate policy intentionally does not promise fairness: B's six operation
requests can all be refused while A holds capacity. Both callers recover; fair scheduling is not
inferred from this finite burst.

Local PCM playback starts at 18,309 ms. At 43,025 ms its time has advanced to 24.744 seconds while
A is hidden and B is visible. Release at 50,024 ms records `paused=true`, `readyState=0`,
`networkState=0`, no source attribute and a stopped clock. The saved `currentSrc` string is historical,
not proof of a live media resource.

A starts an infinite loop at 53,627 ms. The shell independently removes A at 65,877 ms; A disappears
from native views and its heartbeat stays at 108. B remains usable and advances from 59 to 88 ticks;
the shell advances from 122 to 159. The final status at 75,698 ms has no active receive reservation.
Normal quit exits 0. This rerun confirms child removal and peer/shell liveness, not a new process-exit
measurement or a general CPU scheduling guarantee.

## Failures found and corrected during this experiment

1. Profile `/private/tmp/nooki-profile-UsDZu1`: navigating from inside `with_webview` re-entered the
   framework dispatcher and stalled initialization. The dedicated test process was terminated;
   removal of the native handler and subsequent navigation now run as separate ordered operations.
2. Profile `/private/tmp/nooki-profile-nsQr3j`: B's recovery/report check ran while A still held
   capacity. The fixture now waits for the peer's bounded two-second work before checking recovery.
3. Profile `/private/tmp/nooki-profile-jyJl5u`: playback failed because the replacement reply omitted
   Content-Length. Wry's original response code adds it automatically. Restoring it fixes the final
   measured playback, hidden playback and release sequence.

These runs are debugging evidence, not acceptance passes. No production functionality was changed
to conceal the failures. Raw stderr is not attached because the pinned framework prints an ephemeral
invoke key for the deliberately invalid-key test; retained structured events contain no such key.

## Limits and the remaining decision

This closes the measured **Nooki-owned receive copy/decode** gap for this opt-in arrangement. It does
not prove a hard bound on WebKit's earlier request objects, internal buffers, native allocations,
process memory or work involved in rejecting an arrival flood. The probe's diagnostic vector is count-capped at 256 events. This corrects the earlier receipt's
wording; it is still a finite-run evidence collector, not a production logging implementation with
its own byte budget, retention and overflow reporting.
No sustained flood, OOM or total-RSS assertion is made.

Native stream handling is verified with actual NSInputStream objects in unit tests; the desktop
HTTPBody/HTTPBodyStream selection is not separately instrumented, so the desktop run does not claim
that WebKit selected its streaming branch. Delayed-resource cancellation and abandoned-dispatch
cleanup are measured; process-crash recovery and noncooperative host providers are not.

P02e3 must reconcile these limits with the host-availability invariant, exact engine support,
unstable/private interfaces, production ownership, bounded diagnostics/output and encoding-aware
wire/chunk sizing. In particular, a 64 KiB raw chunk plus JSON/base64/envelope is larger than a 64 KiB
wire request. The old 64 KiB payload timing fixture is not a valid receive-mode boundary fixture.
The previous P02e1 baseline remains available with `runtime-probe-embedded` alone.

P02e2 records a verified experiment, not final acceptance of the runtime topology. P02e/P02/K0 stay
pending; the existing trusted-only loader remains in place. Prior network/channel/storage evidence
is retained, but those complete suites are not claimed as rerun in this increment.

## Reproduction and verification

```sh
cd src-tauri
cargo test --offline --example capability_runtime_probe --features runtime-probe-receive
cargo build --offline --example capability_runtime_probe --features runtime-probe-receive
```

Use the temporary app bundle described by P02a and a fresh profile from `desktop-profile.mjs`.
Select the embedded workspace, play A's test audio, run **Run receive boundary probe**, switch to B,
inspect native status after both results, return to A and release audio. Start the infinite loop,
destroy A from the shell, show B, inspect status and quit normally. Do not run the older full boundary
fixture as a substitute: it assumes a payload budget rather than the new complete wire-body budget.

All **11 receive-mode tests** and **9 default-mode tests** pass. They include owner/rate recovery,
exact/overflow stream limits, failed reads, NSString UTF-8 sizing, native NSInputStream boundaries
and existing command/admission tests. Default mode reports two unused-constant warnings for metadata
limits used only by the native feature. JavaScript syntax and `git diff --check` pass. Independent
assertions over all 110 retained events verify both reports, denials, cancellation/late replies,
recovery, absence of old ingress observations, quota release, media and independent removal.

Logs: `/tmp/nooki-receive-tests.log`, `/tmp/nooki-receive-default-tests.log`,
`/tmp/nooki-receive-build.log`. Direct dependencies added to the example are already pinned transitive
crates and remain macOS dev-dependencies; no crate version changed.

The final default desktop build passes (32.70-second native release build, 24.14 MiB bundle), with
only the existing large-chunk advisory. Local reinstall and
`codesign --verify --deep --strict /Applications/Nooki.app` pass. Logs:
`/tmp/nooki-receive-app-build.log`, `/tmp/nooki-receive-app-install.log`.
