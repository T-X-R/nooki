# C03b1: Retained selected inputs for native user tasks

- Date: 2026-11-20; source is this receipt's commit, based on `7d171e3`.
- Branch: `codex/capability-platform-design`; [PR #38](https://github.com/T-X-R/nooki/pull/38), human merge pending.
- Scope: native snapshot capture, Goals input preparation and task-source validation during restore.
  C03b2 still owns renderer delegation/citation UI; C03c owns public sourced creation and archive acceptance.

## Behavior

Native user tasks accept existing plain `{id, title}` sources and selected `{id, title, reference}`
sources. Source entries must be objects with unique document IDs, at most 50. A selected reference
must have the five canonical grant fields, match the outer ID/title, use the supported document kind
and contain a valid grant ID and revision. The same validator is used for worker admission, stored
board loading and backup/restore validation; malformed references cannot silently become plain IDs.

Goals add, prepare and brief generation now capture complete sources. Plain sources still read the
current Library document on first capture. Selected sources read the retained grant body and compare
its complete canonical reference before use. A missing grant, changed reference or absent content
fails without falling back to the current Library document. Both new and reused task captures enforce
the aggregate 8,000,000-byte limit. No partial snapshot/card is saved on a capture-validation failure.

These are user-owned references: editing/deleting the original, revoking a package grant or uninstalling
its package does not invalidate the user's retained input. This read path does not issue permission
or reactivate package access. Package-side reads and C03a new-card creation keep their current
permission/generation/revocation checks. Capturing input does not by itself delegate a capability todo.

The worker holds `task-data.lock`; capture checks the restore guard before reading or reusing data.
Each Library/grant read uses the Library lock without reacquiring the task lock. Captured selected
references retain their grant identity and acquire a task snapshot ID. Existing task snapshots are
reused without needing the original document or grant file; mismatched selections fail rather than
overwrite saved input. The existing ID-only conversation capture API remains compatible and unchanged
in behavior; it can continue reading an already-captured snapshot by the saved document ID set.

Repeated native `add` for an existing task compares its source selection before returning the existing
board. Reordering the same sources does not change identity; a different grant/revision or source title
does. This increment does not introduce full idempotency semantics for every legacy task field.

## Failure reproduction and review

Three tests initially failed on the old implementation: native delegation read changed current text,
an ID-only snapshot was silently reused for a selected source, and malformed references passed backup
validation. Log: `/tmp/nooki-c03b1-red.log` (**19 passed / 3 failed**).

A bounded fresh-context review found two actionable issues in the first implementation:

1. Existing-task `add` replay returned before checking the requested source identity.
2. Serde accepted an array-shaped source as a struct, bypassing raw object/reference checks.

Both were independently reproduced by added tests (**24 passed / 2 failed** in
`/tmp/nooki-c03b1-review-red.log`), then fixed with pre-deserialization object checks and source
comparison before replay. The second review cycle found no further concrete issues in the scoped
capture/replay/restore paths; the review stopped there. Two compile-time ownership/lifetime errors
during implementation were corrected before the final successful run.

Additional regression evidence covers:

- Explicit native user creation after edit, revoke, uninstall and permanent original deletion retains
  the selected body; package reads remain denied. Removing the grant after capture does not prevent
  initial Goals execution from reading the saved brief. Worker restart/stop leaves snapshot bytes intact.
- A changed canonical grant for the same document blocks startup before an agent thread is created.
- Missing grants and mismatched orphaned snapshots leave no new card or snapshot.
- Null/incomplete/mismatched references and array-shaped entries fail admission and backup validation.
- Plain sources capture current-at-delegation text once; later edits do not change the brief.
- 10 MB across separate grants is refused; the exact 8 MB boundary succeeds in native user capture.
- Existing board-create no-execution, grant lifecycle, Goals and Library/restore regressions remain green.
