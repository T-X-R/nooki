## Experiment and reproduction

The opt-in `runtime-probe-embedded` Cargo feature enables Tauri child-view APIs. Normal application
builds do not enable this feature or `tauri/unstable`. The same executable retains separate-window
mode when the feature is absent; no dependency versions or production permission files change.

Embedded mode puts shell, A and B inside one native `probe-workspace` window. Shell occupies the
left pane; A/B share the right pane and shell switches them using native show/hide. The permissive
network control and unavailable-selector control have their own windows. Every view retains the
P02b2b1 pre-creation configuration and independent nonpersistent store. A uses CSP plus native
network controls; B omits CSP as a native-only control. Fixed geometry is an experiment fixture,
not production responsive layout.

Native commands now receive `Webview`, not `WebviewWindow`. Authorization uses the view label;
`probe_identity` reports the native view and parent-window labels for comparison. Core title-change
permission is granted specifically to `probe-shell` via `webviews`, with no containing-window grant.
Shell and packages attempt the same operation against the actual host window. Embedded stop calls
`Webview.close()` on A; separate-window mode still destroys A's window.

Pinned Tauri source explains why this matters: `Capability.windows` grants all webviews in a matching
window regardless of `webviews`; the latter supports specific-view grants. `Window.add_child`
requires the unstable feature, and `Webview.close` removes the child and manager registration. These
source constraints are backed by the observed native identities and positive/negative checks below.

Build the embedded mode in `src-tauri`:

```sh
cargo build --offline --example capability_runtime_probe --features runtime-probe-embedded
```

Use the temporary-bundle procedure in [P02a](P02a.md), copy that executable into the probe bundle,
create a fresh profile with `node scripts/desktop-profile.mjs create`, and launch through the profile
helper. The final run used:

```sh
node scripts/desktop-profile.mjs launch /private/tmp/nooki-profile-gKzTvo '/tmp/nooki-p02b/Nooki Runtime Probe.app/Contents/MacOS/probe'
```

Use a newly created profile when reproducing. The synthetic fixtures use silent PCM audio and
loopback receivers; no ordinary profile, credentials, external services or real agent are involved.

1. Select the embedded workspace from the Window menu. Run channel scope first, then boundary probes.
2. Play A's audio, select B through the shell, request native status, return to A and pause/release.
3. Run additional network probes. The permissive control intentionally navigates away from its fixture.
4. Show B, start A's loop, request status, destroy A, request status again and inspect the recorded
   WebContent process IDs. Play and release B's audio after A has exited.
5. Quit normally. The final process exited with code 0, with no watchdog event.

A local screenshot of shell and B after A's removal is `/tmp/nooki-p02b/embedded-after-stop.png`.

| Return and release | Returning to A preserves its live audio object and page content. Pause/release at 76,378 ms reports stopped advancement, paused true, ready/network states 0 and no source attribute; historical `currentSrc` remains |
| Network controls | All 15 receiver self-checks pass. Restricted shell/A/B record zero HTTP, UDP or preconnect traffic. Permissive control records 13 HTTP paths, 8 UDP packets and 1 preconnect |
| Missing native control | Unsupported-selector view stays blank and never reports package script startup |
| Host responsiveness during loop | At 99,915 ms A starts looping. Its heartbeat stays at 284 and PID 2219 reaches 91.2% CPU; by 110,379 ms shell advances 341→351 and B 144→155 |
| Independent child removal | A is removed from native view inventory at the 114,496 ms close dispatch and remains absent at 119,906 ms. PID 2219 exits; shell PID 2217 and B PID 2220 remain alive in the same containing window |
| Peer interaction after removal | B starts audio successfully at 136,453 ms and releases it at 140,722 ms; shell management and the B page remain visible and responsive |

The HTTP control paths are fetch, beacon, socket, image, frame, style, preload, script, eventsource,
worker, form, media and navigation. Constructor success is not treated as connection success.
The control's heartbeat stops after intentional navigation, so it is not a responsiveness control
for the later loop. Hidden views are timer-throttled; heartbeat counts are not a fixed-rate service
scheduling guarantee. Native view removal is synchronous in the manager, but neither the 0 ms
command dispatch nor the later process sample is a measured process-termination latency.

## Failed attempts retained

The original startup-only run (`joeY0m`) could not be operated because the native desktop tool
reported a locked Mac. After the user reported unlocking, a fresh tool session still returned the
same error; that did not establish that the user's screen was actually locked. The executable
reached its five-minute watchdog and exited 1. Desktop access later recovered; no UI acceptance
is inferred from the startup/watchdog trace.

The first interactive run (`ReEsr2`, SHA-256
`0831067b4d453eef3f7a6a956a97170d7289100e0ef8d9fe4db24a3695387217`) used `title` instead of the pinned
Tauri command's required `value` argument. Package ACL denial was observed, but shell authorization
could not be established by a successful action because argument decoding failed. The probe was
corrected against the installed `@tauri-apps/api/window.js` and native setter definition, then the
entire sequence reran on a fresh profile. That initial run exited normally and remains evidence of
a failed positive control, not a permission pass.

This verifies the scoped embedded-view experiment on the measured macOS engine. It does not ship
an integrated production runtime, service lifetime across page destruction, responsive geometry,
modal/focus/IME behavior, arbitrary codecs, descriptor counts or general OS support. WebKit controls
remain private SPI and Tauri child views require an unstable API. DNS has no packet-level positive
control; prefetch has no observed positive traffic; Service Worker registration and
WebTransport/WebSocketStream remain unavailable in this fixture/engine. The 64 KiB payload guard
is not an allocation bound; production channel generations and other internal IPC exceptions still
require audit. These limits are unchanged by successful same-window tests.
