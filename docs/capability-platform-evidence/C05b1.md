## Delivered boundary

A native proposal contains title, draft text and exact selected-document references. It cannot
supply a conversation target, recipient override inside its content, or document bodies. The trusted
Host controller supplies installed package identity/version and a correlation ID. Pending review
handles remain internal to the Host; these functions do not provide hostile shared-realm isolation.

`begin` requires the main Host caller, a current enabled installation with the handoff permission,
valid bounded content and a stable request/key binding. It either returns an internal review handle
or the original committed receipt for an identical proposal. Receipt lookup checks current permission
and installation but does not recapture revoked sources or expose their retained text. A lookup is
metadata replay, not fresh navigation/send authorization.

`commit` accepts only the Host caller's chosen target for that pending proposal. The first commit
attempt freezes it even if target/source checks or persistence fail. The C05a store holds task-data
and authority fences through installation/restore checks, source capture and draft/receipt commit.
Selected sources must belong to the same current installation, include the exact approved revision
and still have active document grants for a new effect. Disabling/re-enabling the package or restoring
user data invalidates pending review. Cancellation/expiry prevents new effects but does not undo an
already committed user-owned draft.

The target validation callback belongs to the native conversation owner and runs only for a new
effect. Tests provide deterministic target success/failure here. **Actual conversation discovery and
validation are not connected yet**; C05b2 must supply them before exposing a Tauri/public handoff path.
No conversation history is returned, no ordinary composer text is changed and no Agent is started.
No general conversation read/grant/list API was added to the package contract.

Review admission is bounded to 16 pending sessions, 15-minute expiry and 64 KiB request envelopes.
C05a's retained content/receipt limits still apply. Pending -> data -> authority is the common lock
order for both begin/lookup and commit. Exact proposal replay restores its original target/receipt;
changed input or a competing target cannot repurpose the key.

## Tests and review

Ten focused native controller tests pass:

1. Main-Host caller requirement, no effect before approval, exact commit/restart replay and absence
   of Agent session/execution files.
2. Dismissal and unavailable-target failure without a draft; target stays frozen across retry.
3. Changed proposal, request identity or selected target conflicts.
4. Foreign package document references and source revocation fail at effect time.
5. Committed text remains retained and exact receipt replay succeeds after source revocation.
6. Disable/re-enable and completed restore invalidate pending review.
7. Failed staging write preserves the frozen approval; retry commits only once.
8. Permission floor, missing permission, caller-supplied target in a proposal, and expired handle
   fail closed.
9. Competing reviews cannot move one key to another target; a correlation ID cannot switch to a
   different already-committed key.
10. Capacity is bounded/released by cancellation; wrong version and disabled-package receipt lookup
    fail while the user's retained draft remains.

The initial missing-controller test failed (`/tmp/nooki-c05b1-red.log`). Bounded source review then
identified that committed-receipt lookup happened before checking an existing correlation identity.
A new test reproduced returning the wrong committed key's receipt. The fix checks identity under the
same pending/data/authority lock order before lookup; the test now passes. Failure evidence:
`/tmp/nooki-c05b1-correlation-red.log`. This was a local implementation defect corrected before delivery.

Verification commands:
