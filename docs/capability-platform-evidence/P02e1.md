## Finding

P02c bounds operations after admission. The pinned framework has earlier paths that allocate and
decode package-controlled data before the application's dispatcher or asset handler can reject it.
This applies to both IPC and custom resource protocols. Returning an error/403 is therefore not
evidence that the body was refused before materialization.

The finite native probe sends exactly two sequential requests per package, each with **1,048,576
synthetic ASCII bytes**: an unlisted `probe_ingress` command and a POST to the unlisted
`nookiprobe://localhost/budget-ingress` resource path. Both commands remain forbidden. Instrumentation
records only byte counts at existing entrypoints; it introduces no permission grant or business effect.

| Caller | Decoded payload observed at application dispatch | Body observed at custom-protocol handler | Final results |
|---|---:|---:|---|
| A, CSP plus native controls | 1,048,576 bytes at 17,490 ms | 1,048,576 bytes at 17,500 ms | Command denied; resource HTTP 403 |
| B, native-only control | 1,048,576 bytes at 17,496 ms | 1,048,576 bytes at 17,502 ms | Command denied; resource HTTP 403 |

Each package completes its finite pair in approximately 21–22 ms. At 28,577 ms the host status still
works; shell/A/B heartbeats advance from 41/41/15 at dispatch to 85/68/43. Switching to B also works.
The P02c operation pool's current and peak bytes/counts remain zero throughout: these paths never
enter `probe_load`. Normal quit exits 0, with no watchdog termination.

This establishes receive work outside the tested operation budget. It does **not** establish an
observed crash, OOM, measured peak RSS, sustained-flood behavior or a precise engine limit. The probe
does not increase request size until the user's machine fails. Existing command authorization still
denies both attempts; this is an allocation/availability boundary gap, not privilege escalation.

## Pinned owning-source trace

The following locations were inspected in the exact cached crate versions selected by `Cargo.lock`:

| Path | Source location | Order relevant to the finding |
|---|---|---|
| Native script-message receiver | Wry 0.57.1 `src/wkwebview/class/wry_web_view_delegate.rs:47–60` | Gets the NSString UTF-8 view, copies it into a Rust String, then calls the IPC handler |
| Tauri script-message decoder | Tauri 2.12.5 `src/ipc/protocol.rs:294–314` | Deserializes the entire `Message`, including payload, before `webview.on_message` |
| Custom protocol receiver | Wry 0.57.1 `src/wkwebview/class/url_scheme_handler.rs:108–119`, callback at line 320 | Copies HTTPBody into a Vec or appends the body stream before the registered callback; there is no body-length budget on this path |
| Tauri custom-protocol IPC decoder | Tauri 2.12.5 `src/ipc/protocol.rs:434–526` | Parses the received body into JSON before handing the invocation onward |
| Application dispatch/ACL | Tauri 2.12.5 `src/webview/mod.rs:2053–2165` | Resolves permission and invokes the application handler after the receiving/decoding stages |
| Automatic protocol exposure | Tauri 2.12.5 `src/manager/webview.rs:281–286` | Registers the IPC protocol when not already supplied; removing an SDK helper does not remove native receiving routes |

The asset handler receives the same Wry-owned request-body conversion even though it never executes
a Host command. A handler-level method/path check or new broker semaphore alone would be too late
to bound that conversion. The SDK reproduction does not separately instrument which Tauri transport
it selects; the source audit covers both receiver implementations, while the native trace proves
the decoded-dispatch and asset-handler observations above. Neither observation is mislabeled a
measurement of WebKit's earlier internal buffer allocation.

## Decision and next experiment

Do not select the unchanged Tauri/Wry receive path as the completed bounded runtime. P02e2 must
place limits at an auditable native receiving layer (or select another arrangement) before
Nooki-controlled unbounded copying/decoding. It must cover script messages **and every exposed custom
protocol**, including resource requests, rather than only the public Host command.

Prefer a minimal source-level receive hook over runtime method swizzling or a large speculative
replacement runtime. Its probe must cover body length, finite rate/queue limits, streamed-body/error
handling, oversized URL/header metadata, cancellation and small valid calls/assets. Treat already
allocated WebKit/native objects separately; a callback length check cannot by itself prove total
host-memory containment. If the remaining engine behavior cannot meet host availability, keep the
failure visible and evaluate a stronger process/transport arrangement. No alternative is approved
solely because its diagram looks isolated.

P02e3 will reconcile that experiment with all existing evidence, choose encoding-aware chunk sizes,
and record exact support and fail-closed behavior. Until then the ordinary trusted-only loader stays
unchanged. An unsupported new runtime must not make retained Library output inaccessible. K0 remains
closed and C01–C09 do not start; the full implementation objective is unchanged.

## Reproduction and verification

Use P02a's temporary app bundle and a fresh isolated profile. This run launched with:

```sh
node scripts/desktop-profile.mjs launch /private/tmp/nooki-profile-E8ygMS '/tmp/nooki-p02b/Nooki Runtime Probe.app/Contents/MacOS/probe'
```

status, and quit normally. Inspect `events.json` for both byte-count stages and the final denials.
Independent assertions over the retained events verify both callers, exact byte counts, status 403,
command denial, progressing heartbeats and untouched operation-admission peaks.

`probe_ingress` in the denied-command set. JavaScript syntax and `git diff --check` pass. Logs:
`/tmp/nooki-ingress-tests.log`, `/tmp/nooki-ingress-build.log`. This focused run does not rerun or
supersede the prior channel/network/audio sequences and does not claim broad hostile-package support.

The default desktop build passes (32.23-second native build, 24.14 MiB bundle), with the existing
