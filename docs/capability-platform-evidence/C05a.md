# C05a: Retained handoff drafts and atomic replay receipts

- Date: 2026-11-26; existing `codex/capability-platform-design` branch and PR #38, based on `b2620f8`.
- **Status: complete as an internal storage slice.** Native regression and desktop delivery pass.
- Parent C05 remains open. No public capability method, new permission or Tauri handoff command is
  exported in this storage slice. Platform/contract 0.9.0 and kit 0.8.0 remain unchanged.

## Boundary and rationale

Current composer drafts live in a renderer map. Creating a native conversation can connect to an
Agent adapter. Handoff must first retain a user-owned offer without changing that map, creating an
Agent session or sending a turn. `conversation_handoffs` therefore stores offered draft text,
selected source snapshots, the host-approved target and a metadata-only receipt in one native file.
It does not store conversation history or introduce a second execution owner.

`commit_approved` is an internal native effect owner. The future C05b host controller must derive
package identity/version, freeze the user's approved target/intent, validate installation/lifecycle
and restore scope, and authorize selected sources. Its authorization callback runs on every attempt,
including replay, while the existing task-data and capability-authority fences are held. Source
capture runs only for a new effect under those fences. Callbacks must not reacquire those locks.
This slice tests callback ordering/failure and storage semantics, not the missing C05b approval policy.
The public Rust function is not registered as a Tauri command or exposed through the package Host.

Each capability/key pair binds the exact title, draft text, target and selected reference list.
Changed input or target conflicts. Exact replay returns the original draft receipt without
recapturing source text, including after reopening the native store. Capture must match the approved
references exactly and include retained text. Original producer version is retained on replay.
Draft IDs are host-owned identities, not package read grants; host-only list/read returns user data.

The bounded store retains at most 256 drafts/receipts, 50 selected references per draft, 20,000 draft
text characters, 120 title characters, 8 MB of aggregate text and 12 MB of serialized data. Reaching a
limit preserves existing records. File writes sync a staging file, rename the combined draft/receipt
ledger and confirm durability; uncertain post-rename acknowledgement is `OUTCOME_UNKNOWN`. Replay
confirms the visible receipt before returning. No eviction silently discards idempotency state.

The ledger is included in the existing user-data backup/restore roots. Validation checks structure,
content/count bounds, source references, receipt targets and request fingerprints. Invalid state is
rejected instead of treated as an empty store. Restored content conveys no execution or package grant.
C05b must invalidate pending approval across restore; retaining these records does not authorize new
handoffs or sending their text.

## Evidence

The first focused test run failed because the storage module did not exist (after fixing a test-only
call to a private nonce helper). Eleven native integration tests now pass:

- Exact replay/reopening retains one draft, original source text and producer version, with no
  Agent/session/task execution files created.
- Changed text, selected sources or conversation target conflicts; separate packages have separate
  idempotency namespaces.
- Failed source capture and a blocked staging write leave no receipt; exact retry commits once.
- Missing text or mismatched captured references is rejected.
- Source-free drafts retain their approved target without altering another stored draft.
- Invalid/oversized inputs fail before capture; oversized retained text cannot commit.
- Backup/restore retains drafts/receipts; a forged receipt target fails backup validation.
- Malformed disk state remains untouched and fails closed.
- Authorization failure prevents both new commit and replay without altering stored state.
- A concurrent request cannot enter between authorization and commit; after release it replays the
  same receipt. This is native thread/file-lock evidence, not an installed cross-process race claim.
- Real native Library publication/selection supplies retained text. Deleting that synthetic source,
  uninstalling its producer and reloading `PlatformState` leaves the retained draft readable. This
  uses native APIs in a synthetic temporary root, not the desktop UI or a live Agent.
