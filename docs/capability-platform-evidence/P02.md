## Initial composed resource policy

These values guide implementation and are not new public constants in the current kit. A revised
limit needs updated evidence and contract/kit documentation; no silent unlimited fallback is allowed.

| Resource | Initial policy | Owner and remaining integration |
|---|---|---|
| Complete request and IPC response | 65,536 serialized bytes; UTF-8 wire bytes, not JavaScript characters or decoded payload size | R02 framing, bounded response construction, decode validation and errors |
| Transfer chunk | 32,768 raw bytes; base64 is 43,692 bytes; serialized envelope excluding base64 content at most 8,192 bytes | R02/R07; count escaping, keys, IDs and metadata after serialization; also enforce final 65,536-byte limit |
| Request metadata | URL 2,048 bytes; 32 headers; names 128/value 4,096 bytes; headers total 8,192 bytes | R02 native receive checks before owned copy |
| Receive admission | 24 requests/sec/native runtime; four in flight per owner; at most four across the initial two active package runtimes, 256 KiB body reservations; immediate refusal, no hidden wait queue | R02/R03 admission and activation count; larger capacity requires measured revision |
| Host operations | Four/caller, six total, 256 KiB admitted payloads as measured by P02c; effective admission is intersection with receive/run budgets | C01/C06/R02; management stop/revoke stays outside package capacity |
| ZIP | 32 MiB compressed / 64 MiB expanded / 16 MiB entry / 256 entries; serialize inspection and reserve staging before extraction | R01 inspector; do not weaken traversal, symlink or duplicate rejection |
| Private content | 256 KiB value, 16 MiB/256 keys per store; 64 MiB/1,024 files/16 stores shared; four writers | R02/R03; chunk values larger than a wire message; R11 crash/replacement accounting |
| Binary content | 64 MiB item, 128 MiB/four items per store; 256 MiB/16 files/eight stores shared; four writers | R07/R11; retain user outputs, no quota-triggered deletion; 64 KiB disk writes do not define transport chunks |
| Notifications | 16 KiB payload; 64/256 KiB per owner; 128/512 KiB total, including delivered-but-held data | C06/R02; reject newest on overflow and expose resynchronization; bounded operational diagnostics separately |
| Runs | Two per owner / four total | C06/C07/R04; durable identity, late-effect revocation and actual agent cancellation |
| Services | One per owner / two total | R05; own actual handles and await release; independent host work retains its separate ownership |

The retained [Node serialized-byte check](P02-wire-budget.json) on the selected chunk yields 43,692 base64 bytes. With the entire **already
serialized** non-content envelope limited to 8,192 bytes, the total is at most **51,884 bytes**, below
65,536. A representative serialized envelope uses 291 bytes (43,983 total). In contrast, encoding
65,536 raw bytes alone yields 87,384 bytes and must fail. UTF-8/JSON escaping is counted in the
serialized envelope allowance, so this is not an assumption that an 8 KiB source string serializes
to 8 KiB. SDK integration and actual file transfers over this framing remain R02/R07 acceptance.

## Support, failure and architectural limits

The measured combination is the initial development/support target for the new runtime. It is not
permission to enable it on every macOS version or on another architecture. Before production package
activation, R02/R03 must match the supported OS/build, WebKit version and pinned framework behavior,
verify the required native setters/getters, isolated data store and receiver installation, and fail
closed on any mismatch. An OS/browser/framework update requires requalification, not just successful
selector lookup. Windows/Linux and other macOS combinations remain unqualified.

Unavailable new-runtime activation must give a host-owned explanation. It must not erase packages,
private data, documents or artifacts, block ordinary Library viewing/export, or silently execute a
new-format package in the legacy shared realm. Legacy packages retain their explicitly trusted-only
status until the planned migration. This fail-closed product path is a production R02/R03 obligation;
P02 proves the unavailable-control loading refusal, not that the final product UI already exists.

The selected boundary depends on WebKit's engine and OS isolation. It does not promise survival of
an OS-wide memory shortage, an engine vulnerability, arbitrary maximum-rate hostile traffic or
unbounded provider output. These are not newly added K0 proof obligations. Conversely, observed
escapes or loss of host disable in required finite cases cannot be accepted merely by writing a
limitation. The measured app-command, WebRTC, preconnect and owned receive-copy gaps were repaired,
and both loop-stop and stop-under-rejection-pressure cases pass.

Apple's [WKURLSchemeTask contract](https://developer.apple.com/documentation/webkit/wkurlschemetask)
delivers an existing request object to a scheme handler. Current upstream WebKit also places the
encoded request body in [URLSchemeTaskParameters](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/Shared/URLSchemeTaskParameters.serialization.in), retains it in a
[UIProcess task](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/WebURLSchemeTask.cpp),
then calls the [Cocoa handler](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/Cocoa/WebURLSchemeHandlerCocoa.mm).
These sources explain why the receive counter is not total RSS. Upstream `main` is explanatory,
not proof of the exact installed binary's implementation or a claim that every earlier allocation
has an application-controlled cap. No callback check is relabeled an OS memory limit.

Egress coverage remains scoped: TCP/HTTP/UDP/preconnect have working receiver controls and repeated
negative results; DNS-prefetch has a disabled native getter but no packet capture; prefetch has no
positive traffic; service-worker registration is unavailable on the fixture scheme; WebTransport and
WebSocketStream are absent even in controls. R02/R03 must repeat the relevant suite and deny new or
unqualified engine behavior before expanding the support matrix. Private SPI and unstable Tauri
integration are accepted maintenance costs for this narrow path, not cross-platform API promises.

## Review reconciliation and next step

One bounded independent review identified three actionable gaps: finite stop-under-rejection-pressure
evidence, a composed wire budget and an explicit support choice. P02e3a and this decision address
those gaps. The review also inherited the inaccurate unbounded-diagnostic-vector wording; source
inspection showed the existing 256-event cap, which has been corrected without inventing a failure.
Hard total RSS, fair scheduling, durable production quotas and all real-provider termination were
not substituted for the approved feasibility acceptance.

P02 and its measurement/decision parents can now close, and K0 can pass. **C01 is the next eligible
task:** bind a real Host mutation to host-issued invocation identity and scoped authority. No C01–C09,
R01–R15, T01–T08, K1–K11 or M1–M8 outcome is marked complete by this decision. The production loader
remains unchanged, and R02/R03/K4 must reproduce the chosen boundary inside actual Nooki before
new-runtime activation is enabled.
