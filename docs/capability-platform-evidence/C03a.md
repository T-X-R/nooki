- Date: 2026-11-20; source is this receipt's commit, based on `1b24ee2`.
- Branch: `codex/capability-platform-design`; [PR #38](https://github.com/T-X-R/nooki/pull/38), human merge pending.
- Scope: native C03a only. C03b owns task-reference UI/delegation preservation; C03c owns public Host,
  contract/kit delivery and real-archive acceptance. Parent C03 and K1 remain unfinished.

## Authority and transaction behavior

The native board-create input now accepts up to 50 unique selected-document references within its
existing 64 KiB wire bound. Each reference has exactly the five existing fields (`kind`, `documentId`,
`title`, `grantId`, `revision`); unsupported kinds, unknown fields and duplicate document IDs fail.
This stage deliberately keeps one reference per document, matching the existing task source identity.

For a new effect the task worker already holds `task-data.lock`; its board-authority fence remains
held through source validation and the atomic board/receipt commit. The selected-document check
reloads current registry permission and generation without reacquiring either lock, then reads grants
under the existing Library lock. It requires the same installation as the board invocation, live
selected-document permission, a non-revoked matching grant, selected membership and exact saved
reference metadata. A package cannot change a source title/revision or supply another package's grant.
The aggregate selected content is bounded at 8,000,000 bytes, even across separate grants.

Only canonical `{id, title, reference}` entries are stored on the task. Source bodies and private
invocation handles are not copied into the board. The item is still `todo`, with native provenance,
no execution authority, no thread, no agent run and no accepted delivery. Card and idempotency receipt
share the same existing board-file commit and durability acknowledgement.

An exact committed retry is resolved before accessing document grants: it returns the original item
reference and creates no new effect. It still requires current board authority and matching input.
Revoking document access therefore blocks a **new** key but does not prevent recovery of an already
committed operation's metadata. It cannot recall content previously delivered or erase the user's
existing task citation. Changed input remains a conflict. Existing source-free receipt hashes retain
their prior serialization; nonempty sources had no previously accepted receipts to migrate.

A prepared but uncommitted data restore now blocks native Host board creation and receipt replay,
including source-free requests. A reproduced test showed that the old replay path could return an
outcome while restore was incomplete. The guard runs while the worker data lock is held and before
authority/effects. This does not change all legacy board commands or claim a general restore audit.

## Tests and review

Six initial acceptance tests failed before implementation: accepted selected references, refusal
semantics, replay after revoke, stale/permission checks, duplicate/count bounds and interrupted-restore
replay. The failures are retained in `/tmp/nooki-c03a-red.log` (12 pass / 6 fail). The first green run
passes all 18 board tests; `/tmp/nooki-c03a-green.log`.

A seventh added test combines five independently granted 2 MB documents. A 10 MB request fails before
any board exists; the exact 8 MB boundary succeeds with four references and a board smaller than
10 KB. Existing tests also exercise actual task-worker IPC, concurrent calls, dropped replies, worker
restart, queued revocation and receipt failure/recovery. New selected-source tests invoke the real
native `GoalWorker::command` with synthetic data and a nonexistent agent executable.

The selected-source cases assert:

- Canonical references, one todo/receipt and no delegated execution; a worker tick leaves it unchanged.
- Source edits and app-state restart retain the original grant snapshot and replay result.
- Foreign, unselected, forged title/revision/kind, unknown/missing grant and unknown authority fields
  produce no task/receipt; explicit revocation and stale generations deny new creation.
- Removing selected-document permission still permits source-free creation with current board authority.
- Exact replay after source revocation preserves board bytes; a new key is denied.
- Duplicate references and more than 50 are rejected, not silently deduplicated or truncated.
- Interrupted restore blocks both new sourced creation and an existing source-free receipt replay.

One bounded fresh-context review examined only source authorization, worker/lifecycle/restore locking
and transaction compatibility. It reported no concrete findings; the stop condition was met after
that cycle. It did not review or approve the unimplemented C03b/C03c paths.

## Deliberate intermediate limits

The public TypeScript adapter continues to reject nonempty sources. Native acceptance does not imply
that the package-visible workflow is delivered. C03b must preserve these references when the user
views or delegates a task; the current legacy delegation path otherwise captures current Library IDs.
No claim is made that this intermediate native slice has solved that behavior. C03c will update the
SDK/kit and prove the assembled flow with an independent archive. No platform/contract version changes
are needed for this internal slice; the public API remains the documented 0.5.0 surface.

The legacy shared-realm loader is still trusted-only. R02/R03/K4 own hostile-code containment and
production resource qualification. C02's outstanding native input observations remain separate.
