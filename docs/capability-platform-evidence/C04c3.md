## Real keyboard defect and correction

On the unlocked pre-fix installed WKWebView, Escape in the empty or nonempty search input did not
close the dialog, while Escape after moving to a checkbox did. This reproduced independently of
the earlier Mac-lock interruption. `LibraryDialog` now handles an unhandled, non-composing Escape
explicitly, prevents the native default and stops propagation; busy dialogs remain open.

After rebuilding and reinstalling, real keyboard opening followed by Escape from both empty and
nonempty search dismissed the picker and restored the opener. The narrow English/light case also
passed. A component fixture verified that Escape during pending confirmation kept the disabled
dialog open, then completed exactly one confirmation and restored focus. IME composition was not
manually exercised; the handler retains the explicit composition/default-prevented guards.
The [fixture instructions](../../tests/ui/fixtures/task-selection/README.md) record the regression.
