## Submission boundary

`host.board.attachDelivery(input, {idempotencyKey})` accepts a task grant ID, an exact `{id,revision}`,
delivery title and 1–50 distinct document references. The package must declare
`board.attach-delivery` and target Nooki 0.9.0 for this method. Selected-source references require
their active read grant and exact revision; plain references require current publication authority
and this package's document namespace. The existing native C04b2 transaction remains authoritative.

The public client validates and copies the bounded request before waiting for native issuance. It
rejects unknown scope/patch fields, unsafe task versions, duplicate/excessive documents, malformed
selection references and task/conversation snapshot references. Native validation still checks the
actual document identity, ownership, current permissions and grant scope at effect time.

Creation and attachment use separate operation-specific invocation handles. The controller derives
package identity/version from its Host; Tauri forwarding derives the actual caller from its webview.
Concurrent calls share the appropriate pending handle, not another operation's authority. Disposal
releases both handles and prevents late issuance from dispatching a write. Once a write has been
dispatched, disposal is not a rollback; the native authority fence determines whether the effect has
already committed. A committed result or uncertain outcome must be handled using its original key
and complete input. The client makes no hidden mutation retry or renderer-side optimistic write.

The contract and exported Skill describe exact replay, stale selections, source permissions, retained
capacity, removal and restore behavior. Preview explicitly returns `UNSUPPORTED_SERVICE`. This
increment adds native command forwarding without changing the native attachment transaction.

## Retained viewing

Task details show a separate **Attached deliveries** section with title, producer/version and time.
The existing Agent delivery, task status and action controls are preserved. Each document expands
to the text retained inside the task board; the viewer neither reads the Library nor uses package
code/storage. Existing native board refresh picks up the transaction's authoritative saved state.

Text is rendered lazily while a document is expanded. Raw HTML is skipped, links are displayed with
their URL as text, images display their alt text and an explicit non-retention label, and Markdown
checkboxes are static symbols. Passive viewing therefore introduces no live source URL element or
task control. Empty text has a localized message. This service retains Markdown text; copying image
or artifact dependencies remains a later planned service, not a silent promise of offline media.

The retained viewer uses the existing task board styling and native disclosure elements. Actual
keyboard expansion, layout and integrated board refresh still require browser/desktop observation.
